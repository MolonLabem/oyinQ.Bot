# Собственные оповещения

Суперадминистратор открывает «Оповещения → Текст», пишет обычный текст до 3500 символов и сохраняет его. Сохранение не создаёт доставок. Затем выбирает сообщества, проверяет текст и получателей в предпросмотре и подтверждает публикацию. К сообщению добавляется контекстная кнопка «Открыть OyinQ». HTML и Markdown не исполняются.

Редактор сохраняет незавершённый ввод локально. Сохранённые сервером тексты неизменяемы и доступны в истории с пагинацией; для другого текста создаётся новое сообщение. После неопределённого результата сохранения повтор используется с тем же идентификатором и текстом. История позволяет найти уже сохранённое сообщение после перезагрузки.

Собственные сообщения имеют идентификатор `custom-<UUID>` в существующей `ReleaseAnnouncements`. Новая таблица, миграция и отдельный отправитель не нужны. Сохранение и постановка в очередь используют PostgreSQL-транзакции и блокировку строки сообщения. Идентификатор запроса защищает повтор сохранения; составной ключ сообщение/сообщество защищает повтор постановки в очередь. Текст проходит серверную проверку длины и экранируется существующим отправителем.

Все новые API проверяют Super Admin через `IAdminAuthorizationService`. Получатели проверяются повторно перед постановкой в очередь и доставкой; известный, но ненастроенный Telegram-чат не становится получателем. Существующий `ReleaseAnnouncementWorker` сохраняет границы Preparing/Delivering и правила Delivered/Failed/DeliveryUnknown. Повтор Failed требует нового предпросмотра и подтверждения; Delivered и DeliveryUnknown не возобновляются. Встроенный выпуск остаётся во вкладке «Выпуск».

## Проверка

- Пустой текст и текст длиннее лимита не сохраняются; ввод `<b>текст</b>` доставляется буквально.
- Сохранение и предпросмотр не отправляют сообщения. Повтор сохранения возвращает ту же запись, другой текст с тем же идентификатором отклоняется.
- Публикация создаёт очередь только выбранных сообществ. Повтор запроса не дублирует доставку.
- В истории можно открыть текст, проверить статусы и подтвердить повтор только неудачных доставок.
- Обычный администратор не видит раздел и получает отказ от всех API оповещений.
- PostgreSQL-тест `CustomAnnouncementConcurrentSaveAndQueue_CreateOneMessageAndDelivery` проверяет конкурентные запросы; тесты с fake Telegram не доказывают доставку в реальный Telegram.
