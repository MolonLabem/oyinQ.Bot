# Журнал изменений для пользователей

`CHANGELOG.md` показывается в «Что нового?». Его читатели — участники, организаторы и администраторы сообществ, а не разработчики. Эти правила применяются ко всем датам, включая прошлые выпуски.

- Писать, что пользователь теперь может сделать, что стало удобнее или какая видимая ошибка исправлена.
- Использовать знакомые названия экранов и действий. Сохранять даты выпусков и не приписывать старому выпуску новые возможности.
- Не включать имена классов, API, таблиц, миграции, транзакции, внутреннюю механику доставки, тесты и деплой. Не перечислять то, что осталось без изменений. Технические подробности хранить в спецификациях и отчётах разработки.
- Если у изменения нет понятного пользовательского результата, отдельная запись в журнале не нужна. Перед завершением пользовательского изменения проверить новую запись и затронутые прошлые записи.

Пример: вместо «Данные сохраняются одной транзакцией» — «При ошибке сохранения игры больше не добавляются частично», если такой видимый дефект действительно исправлен. Вместо «Добавлен worker с дедупликацией» — «После игры организатор получает одно напоминание подтвердить результат».

Короткие тексты групповых объявлений в `docs/releases/**` редактируются только для соответствующей рассылки и не подменяют журнал.
