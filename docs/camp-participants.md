# Участники кэмпа: список, файлы и личные сообщения

Путь администратора: «Управление» → нужный кэмп → «Участники».
В основной таблице доступны поиск по имени, Telegram и городу, фильтры даты и жилья,
счётчик «Показано … из …» и сброс. Имя открывает существующую ссылку на профиль.
На телефоне город и Telegram находятся под именем; на широком экране — в отдельных
столбцах. Заголовок закреплён внутри прокручиваемой таблицы. Нового диалога нет.

В раскрываемой панели «Экспорт и отправка» сначала выбирают всех участников или
текущий результат фильтра. Здесь показаны условия и число строк. Excel — основной
формат, CSV — альтернативный. «Отправить файл мне» отправляет выбранный файл
администратору в личный чат. «Отправить мне» отправляет тот же выбранный список
таблицей в Telegram. Отправка подтверждается только после ответа Telegram.

## Данные и доступ

`CampParticipantAdminService.GetAsync` — единый запрос для экрана, обоих форматов
файлов и сообщений. Источник — `CampRegistrations` конкретного кэмпа, включая
неполные регистрации. Это не список членов Telegram-группы и не составы сборов.
Все четыре маршрута повторно проверяют `IAdminAuthorizationService` для campId:

- `GET /admin/camps/{campId}/participants`
- `GET /admin/camps/{campId}/participants/export/{csv|xlsx}`
- `POST /admin/camps/{campId}/participants/send-to-me`
- `POST /admin/camps/{campId}/participants/export/{csv|xlsx}/send-to-me`

Маршруты находятся в аутентифицированной группе `/api/miniapp`.
Сохраняется существующая политика: глобальный Super Admin, действующее разрешение
OyinQ вместе с актуальным статусом администратора точного чата для обычного
администратора; архивный кэмп доступен, удалённая привязка — нет.
Доступ к клубу-источнику не даёт доступа к кэмпу.

Запрос принимает `search`, `attendanceDate=yyyy-MM-dd` и
`accommodation=needed|not-needed|unanswered`. Фильтрация выполняется на сервере;
возвращаются **все** подходящие регистрации, без страничного ограничения.
`totalCount` и `availableDates` относятся к полному разрешённому списку.
Для файлов/сообщений `scope=all` игнорирует фильтры, `scope=filtered` применяет их.
Оба варианта сохраняют серверный порядок: показанное имя по русской сортировке,
затем внутренний ключ как стабильное разрешение совпадений. Ключ не попадает в отчёт.
Экспорт перечитывает актуальные регистрации; изменения после загрузки экрана могут
изменить число строк в скачанном файле.

Имя выбирается через `CampParticipantPresentation`, затем нормализованный username,
затем «Имя не указано». Telegram ID не подставляется вместо имени в этом отчёте.
Существующий `ParticipantPresentation` строит контактную ссылку. `SelectedDays`
определяет точные даты и количество дней; `DaysStaying` не используется. Пропуски
между выбранными датами не заполняются. Значения жилья `true`, `false`, `null`
показываются как «Нужно», «Не нужно», «Не указано» соответственно.

## Форматы файлов

Одна строка на регистрацию, включая неполную: №, Участник, Telegram, Город,
Даты участия, Количество дней, Жильё. Технических идентификаторов и других данных
профиля в отчёте нет. Без username в столбце Telegram будет «Не указан»; ссылка
`tg://user?id=…` остаётся только в аутентифицированном интерфейсе.
Имя файла включает безопасное имя кэмпа и текущую дату в его часовом поясе.
В Excel над таблицей отдельно указаны кэмп, местное время формирования с часовым
поясом, фильтры и число строк.

CSV использует прежний разделитель **запятую**, UTF-8 с BOM и кавычки вокруг полей;
кавычки внутри удваиваются, переводы строк сохраняются. Общая сериализация
`CsvExportService.BuildCsv` переиспользуется, но защита человекочитаемых текстовых
полей применяется отдельно: если первый значимый символ — `=`, `+`, `-` или `@`,
перед исходным значением добавляется апостроф. Проверка пропускает ведущие пробелы,
управляющие и Unicode format-символы. Это также затрагивает `@username`.
Апостроф может быть виден при импорте: поведение зависит от программы и настроек,
поэтому универсальная безопасность повторного импорта CSV не гарантируется.
Для сохранения текстовых типов предпочтителен XLSX. Формулы для ссылок или текста
не используются. Существующие технические CSV, их заголовки, порядок и значения
не меняются.

XLSX создаётся через [ClosedXML 0.105.1](https://www.nuget.org/packages/ClosedXML/0.105.1)
([MIT](https://github.com/ClosedXML/ClosedXML/blob/develop/LICENSE), .NET Standard 2.0/2.1,
совместим с .NET 10/Linux). Excel/Office на сервере не нужен. Ширины и высоты
задаются без измерения системных шрифтов. Одна страница, форматированная таблица,
автофильтр, закреплённые заголовки, переносы текста; номера и количество дней — числа.
Пользовательские значения задаются текстом; начальный буквальный апостроф сохраняется.
Переводы строк CRLF в текстовых ячейках нормализуются в LF. Макросов, формул и внешних
ссылок на книги нет. Пустой кэмп даёт заголовки без выдуманной строки участника.
Поле длиннее лимита ячейки Excel (32767 символов) явно отклоняется с предложением CSV.

Файлы формируются по запросу в памяти и не сохраняются на сервере. Потоки
освобождаются. HTTP-ответы используют `Cache-Control: no-store`, MIME выбранного
формата и `Content-Disposition` с именем файла. Общий `download` передаёт initData
только заголовком, использует серверное имя файла и поддерживает отмену при закрытии
экрана. Для встроенных браузеров object URL освобождается через минуту после клика.
Публичных ссылок на данные и токенов в query string нет.

## Telegram

Проверена текущая официальная документация:
[sendRichMessage](https://core.telegram.org/bots/api#sendrichmessage),
[InputRichBlockTable](https://core.telegram.org/bots/api#inputrichblocktable),
[лимиты](https://core.telegram.org/bots/api#rich-message-limits).
Используются существующий Telegram.Bot **22.10.2.1**, `InputRichMessage.Blocks`,
`InputRichBlockTable`, `RichBlockTableCell` и `RichTextText`. Версия SDK не меняется.
У ячеек явно задаются поддерживаемые alignment-значения. Пользовательский текст
сериализуется как обычный текст, без HTML/Markdown и автоматического определения
ссылок. Это настоящее rich-сообщение; `<table>` в `sendMessage` не передаётся.

Три столбца: участник с городом/username, все выбранные даты и число дней, жильё.
Сообщения делятся по полным строкам. Кэмп, количество и условия повторяются в каждой
части. Общий консервативный предел — 3900 UTF-8 байт и 80 строк данных на часть:
это также укладывается в обычное сообщение на 4096 символов и в ограничения rich
сообщений (32768 UTF-8 символов, 500 блоков, 20 столбцов). Слишком длинная отдельная
строка вызывает понятное предложение отправить файл; данные не обрезаются.

Кнопка «Открыть список» использует `MiniAppLinkBuilder` и текущий `admin=1` вход,
добавляя `adminCommunity` и `adminSection=participants`. Они выбирают экран из
разрешённого сервером admin overview; недоступный кэмп не заменяется чужим списком.
Любой запрос после открытия ссылки вновь авторизуется.

Fallback — обычный текст с теми же полными строками. Он используется только после
явного отказа неподдерживаемого rich-формата или метода, для текущей и следующих
частей. Ранее доставленные части не повторяются. Таймауты, сетевые ошибки и 5xx
считаются неподтверждённой доставкой, без автоматического повтора. Частичная
отправка сообщает подтверждённое число строк. Интерфейс блокирует повторную отправку
до явного «Проверил личный чат»; скачивание остаётся доступным. Это не детектор
возможностей Telegram-клиента. Если сервер принял сообщение, отображение конкретной
версией мобильного клиента требует ручной проверки.

Получатель определяется исключительно по аутентифицированному actor; адрес из
query/body не используется. Отправки в группу нет. Ошибка запрета личных сообщений
просит открыть чат с ботом и нажать «Старт». Кнопки блокируются на время запроса;
успех не показывается для устаревшего/закрытого экрана. Фоновых заданий и постоянного
хранилища попыток экспорта нет; после перезапуска/перезагрузки перед повтором нужно
свериться с личным чатом.

## Проверка

Регрессии: `CampParticipantExportTests`, `CampParticipantAdminServiceTests`,
`CampParticipants.test.tsx`, `AdminPage.test.tsx`, `download.test.ts`.
HTTP-тесты используют подписанные тестовые initData, EF InMemory и поддельный
Telegram HTTP transport. XLSX повторно открывается и проверяется Open XML Validator.
Поддельные данные включают неполные регистрации, пропущенные дни, формулоподобные
значения, кириллицу, эмодзи, кавычки и управляющие символы.

Перед выпуском вручную проверить на тестовом кэмпе и аккаунте администратора:

1. Excel и CSV из Telegram на Android/iOS, сохранение/открытие файла и имя файла.
2. Нативную rich-таблицу и кнопку перехода к правильному кэмпу.
3. Доставку вложений в личный чат, блокировку бота и отмену запроса.
4. Отзыв доступа после открытия списка и переход по пересланной ссылке обычным участником.

Не использовать настоящие данные участников для отправки в production-группы.
