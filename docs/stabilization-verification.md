# Проверка стабилизации

Быстрые тесты сохраняются. PostgreSQL-проверки находятся в `PostgreSqlStabilizationTests` и включаются переменной `OYINQ_TEST_POSTGRES`. Без неё они явно пропускаются; такой прогон не закрывает релизный gate.

Используйте отдельный локальный тестовый PostgreSQL с правом CREATE DATABASE. Не задавайте production connection string. Каждый тест создаёт собственную базу `oyinq_test_<guid>`, применяет настоящие EF migrations и удаляет только эту базу в Dispose, включая очистку после ошибки подготовки. Внешние BGG/Telegram вызовы заменены фейками. Дополнительных пакетов/контейнерного оркестратора не требуется: используется уже имеющийся Npgsql.

```powershell
$env:OYINQ_TEST_POSTGRES = 'Host=127.0.0.1;Port=15439;Database=postgres;Username=oyinq_test;Pooling=false'
dotnet test oyinQ.Bot.slnx --configuration Release
```

Интеграционные сценарии: оба порядка гонки создания и удаления, локальный откат ownership/contribution/gathering, конкурентные provisioning/upsert и уникальность БД, replay подтверждения из нового scope после expiry, миграция старого Camp fixture с дедупликацией и сохранением регистрации/commitments, конкурентная доставка уведомлений и восстановление терминальных/нетерминальных состояний, восстановление рассылки после подготовки и неизвестной отправки. Задержки в гонках задаются барьерами, а не предположениями о скорости сети.

`AuditRegressionTests` содержит семь бывших красных воспроизведений аудита как постоянные зелёные тесты. Дополнительные состояния покрыты `NotificationDeliveryTests`, `ReleaseAnnouncementTests`, `GlobalProfileApiTests` и Mini App `GlobalProfile.test.tsx`. HTTP-тест глобального профиля использует настоящий маршрутный binding, проверенную подпись initData и пустой список разрешённых сообществ.

Перед выпуском подготовьте Git-индекс, затем выполните `scripts/verify-release-input.ps1`. Сборка локального рабочего дерева недостаточна: экспортируйте подготовленный индекс в отдельную папку через `git checkout-index`, восстановите зависимости и выполните .NET build/test, EF model check, Mini App test/check/build из этой папки. Это включает только будущий состав коммита, без игнорируемых локальных файлов. Не включайте секреты или TestResults.

Отложено намеренно: оптимизация подсчёта популярности по PlayRecord и параллелизация запросов Telegram при подготовке выпуска. Сначала нужны измерения. Эта стабилизация не отправляет объявления, не развёртывает приложение и не мигрирует рабочую базу.
