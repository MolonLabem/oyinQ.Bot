# Проверка выпуска OyinQ — 2026-09-04

Проверялось фактическое рабочее дерево ветки `master` относительно `7494223` (`Restore date emoji on gathering cards`), включая новые файлы, ещё не добавленные в Git. Коммитов и развёртывания в этом проходе не было. Ранее существовавшие изменения сохранены; `Task.md` не редактировался.

## Результат по требованиям

1. **Архитектура.** Сохранены существующие границы идентичности, коллекций, каталогов, сборов и Telegram. Провайдер данных и проверка дополнений общие; Telegram доставляет результаты после сохранения локального состояния. Справочник `/start` и `/help` общий, рассылка использует существующий групповой отправитель.
2. **Миграции.** Пять последовательных миграций этого цикла: `PersistentParticipantCollection`, `CampOperatingInstants`, `NotificationDelivery`, `GatheringPlayRecords`, `PlayOutcomesReferencesAndReleases`. Участники, регистрации, Camp-обязательства, клубные/базовые коллекции и снимки сборов сохраняются. Последняя миграция переносит прежние отрицательные записи в исход сбора с полным служебным аудитом, сохраняя положительные партии. Откат миграций запрещён, чтобы не потерять данные.
3. **Личная коллекция.** `ParticipantCollectionItems` глобальны, уникальны по участнику/BGG ID/типу. Снимок общий с вкладом, но владение не зависит от сообщества. Существующие Camp-вклады безопасно заполняют коллекцию; выход из кэмпа удаляет лишь его доступность. Импорт переиспользует существующие сохранённые задания, `CampId = null` означает профиль.
4. **Первый вход.** Корень ошибки: аутентификация Telegram подтверждала пользователя, но путь участия искал уже существующий Participant; его создание ранее происходило в других точках, например приватном `/start`. Теперь фильтр всей группы Mini App API вызывает `ParticipantIdentityService` до бизнес-кода. Повтор не создаёт второй идентификатор; обновляются доверенные имя/username, сохраняются предпочтительное имя и контекст. Доступ к Camp по-прежнему требует регистрации и выбранного дня. Приватный запуск — отдельная способность, которую Mini App не выставляет.
5. **Время кэмпа.** UTC-границы включают начало и исключают конец. Регистрация использует пересекающиеся локальные даты, с подписями неполных дней. Старый EndDate превращается в полночь следующего дня, поэтому прежний последний день не теряется. Неоднозначное/несуществующее локальное время отклоняется.
6. **Уведомления.** Сохранённые намерения, предпочтения, дедупликация, состояние доставки и повторы явных временных ошибок централизованы. Напоминания выключены по умолчанию, разрешены фиксированные интервалы. Доставка перепроверяет актуальные настройки, время, участие и отмену. Нет приватного запуска или Telegram заблокирован — показывается CTA; вступление в клуб не блокируется. Потерянный ответ Telegram не считается доказанным успехом и не повторяется автоматически.
7. **Пересечение расписания.** Предупреждение 409 `gathering_schedule_conflict` учитывает организацию и подтверждённые записи в разных доступных сообществах. Окно по умолчанию ±120 минут, настраивается. Подтверждение снимает лишь предупреждение, не проверку доступа, регистрации и жизненного цикла.
8. **Коробка.** `GameProviderService` различает базовую коллекцию, подтверждённого владельца, возможных владельцев и отсутствие коробки. Для Camp-игры учитывается дата регистрации. Действие «Я привезу» обновляет существующий Camp-вклад. Личное владение само по себе не публичное обещание принести игру в клуб.
9. **Внешние дополнения.** Существующий GamePicker → `/bgg/game` → `GetGameDetailsAsync` остаётся единственным путём загрузки. В поиске BGG возвращаются базовые игры; детали выбранной игры содержат дополнения. `GatheringExpansionSelection` проверяет подмножество на сервере при создании, изменении и записи партии. Ошибка BGG при отправке формы не сбрасывает выбранные значения; можно повторить.
10. **Личная коробка при создании.** Флажок добавления означает постоянное владение игрой/выбранными дополнениями. Отдельный флажок Camp означает Bringing в этом кэмпе. Локальные изменения находятся в одной транзакции; уже имеющиеся подробные метаданные не затираются кратким снимком. Дополнительного BGG-запроса для владения нет. Без подтверждённой коробки сбор разрешён с видимым предупреждением. Club.CollectionJson не меняется.
11. **Обзор организатора.** Свои сборы, либо все сборы выбранного сообщества для эффективно авторизованного администратора: недобор, очередь, коробка, близкое начало, отмены, публикация и существенные проблемы доставки. Агрегаты кэмпа доступны администратору.
12. **Личный обзор.** Ближайшие записи, организация, начало очереди и возможность помочь с коробкой кэмпа. Ссылки ведут в исходное сообщество. Сохранён прежний календарь через ProfileGatheringQuery, без копии правил расписания.
13. **Поиск.** Club — авторитетная клубная коллекция плюс только личная коллекция текущего пользователя, дедупликация по BGG ID. Camp — базовый снимок плюс явные вклады зарегистрированных участников. Фильтры и карточки используют общие сервисы. Сортировка по популярности опирается на подтверждённые партии, не Completed.
14. **История игр.** Исход подтверждает организатор; автоматического подтверждения, голосования или самостоятельной записи другими игроками в первой версии нет. «Нет» сохраняет исход без партии. Устаревшая ревизия или попытка заменить подтверждённую партию отрицательным исходом дают 409 `play_outcome_conflict`. Подтверждённый состав учитывает реальные выбранные лица; явно отмеченные отсутствующие не выбраны по умолчанию. Посещаемость и снимок сбора не переписываются.
15. **BG Stats.** Только документированная HTTPS createPlay-ссылка, с фактическим окончанием в UTC, стабильными случайными ID и дополнениями в комментарии. Telegram ID/контакты не передаются. Загрузка/скачивание файлов партий, резервные форматы и универсальный экспорт удалены. Имена входят в ссылку: UI это объясняет.
16. **Ссылки игроков.** `GatheringExternalPlayReference`: партия, провайдер BgStats, нормализованный URL, автор, время. Добавляет организатор или фактический игрок; очередь и исключённые лица не получают это право. Удаляет автор или организатор. Точный хост `app.bgstatsapp.com`, HTTPS, без userinfo/нестандартного порта; сервер URL не скачивает. Уникальность закреплена индексом.
17. **Бот.** Рекламируется `/oiynq`, `/oyinq` остаётся только совместимостью. Полное Description обновлено, ShortDescription не изменено. Общий справочник `/start` и `/help` укладывается в лимит сообщения; `/menu` короткий. Runtime-username и существующие форматы переходов сохраняются, в том числе контекст сбора и Camp-импорта.
18. **Объявление выпуска.** Суперадминистратор выбирает получателей, видит текст и явно подтверждает. Одного KnownTelegramChat недостаточно: нужны активное управляемое сообщество и текущее право бота писать. Выпуск и доставка сохраняются, используется тема существующего группового отправителя. Успехи не повторяются, ошибки повторяются только по подтверждению; неопределённый исход требует ручной проверки. Перезапуск сам не создаёт рассылку. Текст встроен из `2026-09-04.md` и фиксируется при первой постановке; изменение текста требует нового release ID.
19. **Очистка.** Удалены отдельная Camp-only страница MyGamesPage, Camp-specific версия общего снимка, старое независимое приветствие, генерация файла JSON партии и одиночный изменяемый URL из рабочего API. Убраны повторные проверки принадлежности дополнения, повторная десериализация личных снимков в Club-проекции и лишний поиск Participant перед приватным provisioning. Legacy-маршруты, ключи localStorage и Camp-import DTO сохранены там, где на них есть реальные ссылки. Проверка импорта не позволяет клиенту выбрать неподдерживаемый элемент черновика.
20. **Проверки.** Итоговые команды и числа приведены ниже. Тесты используют локальные данные, InMemory EF и поддельный HTTP. Они не выдаются за проверку живых BGG/Telegram/PostgreSQL. Полный список новых областей покрыт PlayOutcomeAndReferenceTests, GatheringOwnershipCreationTests, ReleaseAnnouncementTests, GatheringGameSelectionServiceTests, ParticipantCollectionTests, ParticipantIdentityFlowTests, NotificationDeliveryTests, PlanningFeatureTests, ProviderAndDiscoveryTests и тестами Mini App.
21. **Остаточные риски.** Перед production нужны миграция на копии PostgreSQL и проверка одновременных записей/отката транзакции, реальная доставка Telegram и открытие BG Stats на устройстве. У Telegram нет ключа идемпотентности отправки: неизвестный ответ требует ручной проверки, а не обещания exactly-once. Обзоры ограничены 200 строками на группу выборки и показывают усечение; статистика каталога пока читает снимки подтверждённых партий выбранного сообщества — на большом архиве потребуется SQL-агрегация. Проверки фактического состава не являются проверкой реального присутствия: его подтверждает организатор. Ранее запрошенное пополнение BGG-аккаунта пропущено по указанию пользователя; этот проход не менял аккаунт и не выполнял рассылок.

## Итоговая проверка

- `dotnet restore oyinQ.Bot.slnx` — успешно.
- `dotnet build oyinQ.Bot.slnx --configuration Release --no-restore` — успешно, 0 предупреждений и 0 ошибок.
- `dotnet test oyinQ.Bot.slnx --configuration Release --no-build --no-restore` — 433 пройденных теста, 0 пропусков.
- `npm ci --offline --no-audit` — 53 пакета установлены из кэша. Обычный `npm ci` ожидал сетевой аудит и был остановлен; проверка уязвимостей npm в этом прогоне не выполнена.
- `npm run check` и `npm run build` — успешно.
- `npm test` после чистой установки — 70 пройденных тестов в 16 файлах.
- `dotnet ef migrations has-pending-model-changes --configuration Release --no-build` — расхождений нет.
- SQL последней миграции сгенерирован и просмотрен: новая схема, перенос исходов/аудита и ссылок выполняются в одной миграционной транзакции. На живой базе не запускался.
- `git diff --check` — чисто.
- `docker build -t oyinq-bot .` — не выполнен: отсутствует канал `dockerDesktopLinuxEngine`, локальный Docker Engine не запущен.

В production миграции не применялись. Реальные Telegram-рассылки не запускались. Прямое добавление игр в аккаунт BGG не выполнялось.
